# Changsha rules and evidence

`changsha-v1` is the default profile for [the host boundary](architecture.md#rules--host-boundary). It follows the single-bird, single-rolled-replacement profile documented by [Tencent QQ Game][qq], with the specific interpretations below. A room can opt into [Two Birds](#optional-two-birds-changsha-two-bird-v1), which changes only terminal bird scoring. Neither profile is a reconstruction certified by video or a claim that all Changsha tables agree.

## Reducer, projections, and verification

- [`Contracts.cs`][contracts] is the typed boundary for [protocol v1 snapshots][wire]. The host supplies clock and adds room/match/revision metadata, totals, and the display deadline. DTOs already supply phase/option/meld strings in wire casing. `PublicMeld.Method` is null for `chi`/`peng`; `gang`/`bu` make it `open`, `concealed`, or `added`. A concealed meld projects four null faces in `PublicSeat.Melds` in every phase. A terminal `PublicWinner.WinningHand` reveals only that winner's held faces and complete melds; `WinningTiles` contains the separate event tile. `WinPattern.Points` is an unadjusted unit; `Settlement.Transfers` is the authoritative positive `{fromSeat,toSeat,points,reason}` ledger (`win` or `opening`), matching `SeatResults.Delta` exactly. Closed responses, stock, non-winning hidden hands (apart from opening evidence), RNG input and physical tile IDs never appear on the wire.
- [`GameState`][checkpoint] is a server-private immutable checkpoint (System.Text.Json); `CheckpointVersion = 1`, including the persisted pending choices and turn kinds, and `ShuffleVersion = 1`. There is no separate engine event journal: `Choose`/`Expire` are the v1 transition inputs, not snapshots. The HMAC-SHA256 Fisher–Yates stream uses the 128-bit seed in little-endian order and rejection sampling. Independent HMAC domains bind window/option IDs to hand and sequence, options also to seat, and private tile IDs to hand and seat rather than wall position. Dice are derived separately from the completed decision's sequence, not from response order. Host keeps seeds private and namespaces wire windows across rematches.
- Choices close **at** their deadline. Only `Expire` makes progress on time alone, passing optional choices or discarding the drawn tile (otherwise the first legal discard) at the stored cutoff; an overdue restart doesn't reset the next deadline. Opening/rob/discard claim windows open only when at least one seat can respond. The last-tile draw/pass offer has `phase: "turn"`, `reason: "lastTile"` and the claim limit; private draws never add a public trigger. Bots pick only from the same options available through `PublicView` and the bot's own `SeatView`.
- Run `dotnet test tests/Mahjong.Rules.Tests -c Release -p:RestoreLockedMode=true` for successor-only Cha, winning-hand disclosure, committed dice, version compatibility and exact settlements. The four classic seed series below play four reducer hands each, then replay every action and settlement exactly with repeated checkpoint reloads. Forced physical-deck fixtures exercise four consecutive kongs and rare terminal paths.

## Optional Two Birds (`changsha-two-bird-v1`)

Choose this house profile when creating a room; it stays fixed through all deals and rematches in that room. Omit the option for `changsha-v1`, which normally reveals one dealer-anchored bird. Both settle signed, zero-sum hand deltas. The Two Birds profile is one specific house rule, not a universal Hunan standard.

### Where the rules agree and diverge

Rechecked 2026-11-22. Read Tencent's Chinese help directly as GB18030 and Salasasa's Chinese PDF (§§5, 7, 9–12, version dated 2026-07-09). A bird's **rank**, not its suit, counts counterclockwise from the chosen starting seat: **1/5/9** = anchor, **2/6** = next, **3/7** = opposite, **4/8** = previous. In absolute progression order, `hitSeat = (anchorSeat + rank - 1) % 4`. Counting is shared; who the anchor is, who qualifies for a multiplier, and how hits combine are not. In the table, `a/b` means points before birds, per payer: `a` when neither endpoint is dealer, `b` when either endpoint is dealer. Big rates are per scoring unit where the source explains stacking.

### Two Birds scoring

Use **the hand's dealer as the anchor, one shared reveal of up to two birds, and additive endpoint hits**. This keeps v1's payer specificity and scoring table while limiting the largest bird multiplier to `3×` rather than `4×`. It takes the arithmetic progression from MahjongPros and the **per-payer self-draw scope** from QQ/Salasasa; it is not a copy of any publisher's complete profile.

| Award or Hu | Who pays whom | Neither endpoint / dealer at either endpoint | Treatment |
|---|---|---|---|
| Small self-draw | Each other seat to the winner | `1 / 2` | One small unit; terminal birds apply. |
| Small discard | Only the discarder to each winner | `1 / 2` | One small unit; terminal birds apply. |
| Big self-draw | Each other seat to the winner | `3 / 4` per big unit | Add big units before birds. |
| Big discard | Only the discarder to each winner | `6 / 7` per big unit | Same stacking as big self-draw, including applicable context units. |
| Rob Gang | Only the seat whose added tile was robbed, to each winner | `6 / 7` per big unit | The rob contributes one big unit. |
| Rob Bu | Only the seat whose added tile was robbed, to each winner | `1 / 2` if plain, else `6 / 7` per structural big unit | The rob adds no unit. Still a terminal `robKong` result. |
| Opening awards | Each other seat to each qualifying opener, even on a draw | `1 / 2` per accepted award | Separate `opening` rows. No bird or change to the turn/dealer flow. |
| Draw without Hu | No terminal payer or winner | None | No bird; keep any opening rows. |

Once the Hu decision resolves, flip the next **two available** live tiles in wall order, once for the terminal win (not once per claimant). A lack of stock is not a reroll: flip one if only one remains, zero if none. For an actual 海底 win, show its winning tile as one reference bird, not a second physical tile; a kong replacement that empties the wall is not 海底. A draw, including four 海底 passes, flips nothing. For each terminal payer → winner row, sum dealer-adjusted units before applying birds; ordinary small Hu does not add a unit to big Hu. Let `h` be the number of revealed birds landing on either endpoint, `0 ≤ h ≤ 2`. Count each reveal at most once for that row; one bird at each endpoint counts twice, just as two distinct birds at one endpoint do. A bystander's bird never creates a new payer. The row is `sum(adjusted units) × (1 + h)`. Multi-Hu uses the same reveal and starting dealer for all rows and keeps v1's source liability and next-dealer rules.

Keep all other legality and opening rules unchanged. Salasasa's configurable 2–4 kong flips include a different multi-tile Hu, selection, and re-kong flow (§7); those are replacement actions **before** Hu, not the two scoring birds **after** Hu. Importing them would change available actions, wall consumption and even big-unit counts. Its 三同, dice-based opening scoring, alternate dealer pricing, and different missed-Hu and 海底 eligibility also need separate decisions and fixtures. Do not turn them on as side effects of choosing two birds.

### Table points and recovery

Every transfer debits and credits the same amount using checked integer arithmetic. Each settled hand adds its delta to the match total and the same room's table total. A new match in that room resets the match total but keeps the table total and next dealer. Reserving a seat through disconnect or ordinary leave in play does not reset its score; vacating a seat clears only that occupant's running total. Legacy rooms initialize table totals only from the stored match totals still attributable to occupied seats. No points transfer to a different room. Players cannot buy, gift, redeem or exchange points; a negative score is not a debt.

The committed reveal moves real birds out of the private wall exactly once; 海底 is only a reference. The engine uses the same shuffle and checkpoint schema for both profiles. The [commit model][commit-model] writes the resulting checkpoint, room totals and any command receipt together. Recovery restores the original deadline and remaining wall for a pending hand or the saved score and reveal for a settled one. Retrying a command never reveals a new bird or adds its delta again. The [protocol][wire] exposes ordered bird faces, actual transfers and the two scopes of totals without hidden tile IDs, seed or wall order.
